Как забэкапить все бакеты в S3 Yandex Cloud?

posted on 2026-10-12

В прошлом посте я писал рецепт бэкапа виртулок. И мне таки удалось одну самую большую таким образом спасти, а вот с той на которой был развернут Staticbot – не повезло.

Сегодня вспомнил что у меня там ещё и в S3 лежала часть статики для разных сайтиков. Решил забэкапить и их.

Как это сделать? Нужно завести в Яндекс Облаке сервисный аккаунт с правами storage.editor и создать для него статический ключ. Так вы получите идентификатор ключа и секрет.

Дальше создайте с ними такой конфиг для утилиты rclone:


[cloud]
type = s3
provider = Other
access_key_id = XXXXXXXX
secret_access_key = YYYYYYYYY
endpoint = [https://storage.yandexcloud.net](https://storage.yandexcloud.net)
acl = private

и сохраните в файл rclone.conf

После установите саму утилиту. Я предпочитаю через nix-shell. Но можно и любым пакетным менеджером.

Если через nix-shell, то нужно сделать такой файлик shell.nix:


{ pkgs ? import <nixpkgs> {} }:

pkgs.mkShell {
  packages = [ pkgs.rclone ];
}

И запустить в этой директории команду nix-shell - попадете в окружение где доступен rclone.

Ну и финальное, чтобы забэкапить вообще все S3 бакеты до которых сможет дотянуться аккаунт, делаем такой bash скрипт backup.sh:


#!/bin/bash

for bucket in $(rclone --config rclone.conf lsd cloud: 2>&1 | awk '{print $5}');
    do echo "Backing up $bucket";
    rclone --config rclone.conf sync cloud:$bucket ./$bucket/;
done

При запуске, он сначала получит через rclone список доступных бакетов, а потом забэкапит каждый из них в ту же папку откуда запущен.

Как забэкапить виртуалку в Yandex Cloud

posted on 2026-10-09

Ввиду неиллюзорной угрозы потерять данные, решил забэкпить данные своих виртуалок в Яндекс Облаке. Да так, чтобы образа их лежали у меня дома, на жестком диске.

Вот краткая инструкция, как это можно сделать.

  1. Корректно выключи исходную ВМ, чтобы получить согласованное состояние файлов и баз данных.

Update: ПОДОЖДИ СЛЕДОВАТЬ ИНСТРУКЦИИ, Я ТЕПЕРЬ НЕ МОГУ ЗАПУСТИТЬ СВОЮ ВИРТУАЛКУ – ПОЛУЧАЮ ОШИБКУ: Resource allocation is restricted

  1. В консоли открой Compute Cloud → Диски и хранилища → нужный диск → Создать образ. Дождись завершения создания — после этого исходную ВМ можно снова запускать.

  2. Создай временную ВМ с Ubuntu, SSH-доступом и внешним IP. Подключи к ней дополнительный диск, созданный из полученного образа. Её собственный загрузочный диск будет отдельным.

  3. Подключись к временной ВМ и найди диск-копию:

```

lsblk -o NAME,SIZE,TYPE,MOUNTPOINTS,SERIAL

```

Допустим, это /dev/vdb. Нужен весь диск, а не раздел /dev/vdb1. Его разделы должны оставаться непримонтированными; форматировать диск не нужно.

  1. На своём компьютере, в терминале macOS или Linux, запусти:

```shell

ssh USER@HELPER_IP \ "bash -o pipefail -c 'sudo -n dd if=/dev/vdb bs=4M status=progress | gzip -1'" \ > vm-backup.img.gz.part && mv vm-backup.img.gz.part vm-backup.img.gz

```

Замени пользователя, IP и устройство на свои. Команда предполагает, что пользователь временной ВМ может выполнять sudo без пароля. Образ сразу скачивается на компьютер, поэтому хранить его целиком на временной ВМ не требуется.

  1. Проверь скачанный архив:

```shell

gzip -t vm-backup.img.gz

```

При успешной проверке команда завершится без вывода. Для уверенности в восстановлении лучше также проверить загрузку копии в локальном гипервизоре.

Получится полный RAW-образ диска, сжатый gzip. Если у ВМ несколько дисков, сохрани каждый отдельно. После распаковки образ занимает полный размер исходного диска. Настройки самой ВМ — CPU, RAM, сеть, BIOS/UEFI — сохрани отдельно.

Если удобнее получить сразу QCOW2 через Object Storage, у Yandex Cloud есть скрипт yc-disk-export-tool: он создаёт вспомогательную ВМ, экспортирует диск в бакет, откуда файл можно скачать. Для одного бэкапа вариант по SSH требует меньше настройки.
